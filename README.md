# 跃动 · Front Desk Agent 本地 Demo

在线体验：<https://zruihua804.github.io/movement-clinic-agent/>

这是一个无需真实账号、保险或排班接口的公开演示，所有业务数据均为 Mock 数据。

双击 `启动演示.command`，或在本目录运行 `npm start`，然后打开 http://127.0.0.1:4173 。需要 Node.js 20+，无需安装 npm 依赖或填写 API Key。服务仅监听本机；关闭运行服务的终端即停止。

## 会议演示（约 5 分钟）

1. 点击 **ACLR 术后康复**，依次点快捷答案，添加模拟病历，进入医疗审核。
2. 在右侧填写审核意见，尝试 **需要补资料**。患者补充后重新进入审核队列。
3. 选择接诊医生 / PT，点击 **接受并匹配人员**。左侧原会话自动恢复，选择时段完成预约。
4. 点击 **改约**：在新预约成功前保留旧时段；确认新时段后释放旧时段。点击 **取消预约**释放预约。
5. 点击 **Aetna 保险**，完成基础字段后选 International → 模拟可覆盖。Cigna → 人工核验；Bupa → 不支持，可选择自费。
6. 点击 **腕舟骨不愈合**，完成资料后可演示接受、补资料或不适合本机构。
7. 点击 **指定 PT**，仅显示所指定人员的排班。
8. 点击 **急性术后肿胀**，自动暂停预约并转医疗人员。右侧人工回复；记录处理结果并确认风险已处理后，可归还 AI。

所有场景均创建独立 Case，可在工作台切换查看原会话、结构化摘要和公开事件轨迹。人工接管时患者继续发言不会触发 AI 回复。导出演示记录按钮可保存全部 Case JSON。

## 当前范围与限制

- 这是单浏览器、本地产品逻辑原型，患者端和工作人员端在同一页面模拟，无账户或权限隔离。
- 对话采用关键词分流及逐字段问答，不是通用语言模型；请按当轮问题填写，或使用快捷答案。不支持可靠地从一段长文自动提取全部字段，也不支持随时切换既有意图。
- 手术日期校验格式、真实日期及非未来日期。其他文字资料由医疗人员审核；“添加模拟病历”只录入虚构摘要，不读取或上传真实文件。
- 排班为首次打开时生成的未来三天、3 位人员、27 个时段。期望时间作为偏好展示，最终由患者选择具体时段。
- Aetna + International / Cigna / Bupa 只是三种结果的测试映射，不代表任何真实保险政策。
- 预分诊仅演示就诊分流，不输出诊断。风险关键词不是临床筛查规则；本应用不会实际通知医生、急救或第三方。
- 数据使用 localStorage；刷新保留，仅在同一浏览器与地址中共享。无服务端数据库、跨设备同步或多用户事务保障。使用虚构数据演示。

## 代码结构与未来集成

- `adapters.js`：对话分类、Mock 保险查询及排班来源。未来可用 Dify / LangGraph / n8n 返回受约束的意图、字段或流程建议，用 Chatwoot webhook 对接消息。
- `workflow.js`：确定性状态转换、审核门槛、人工控制权和预约占用。外部模型不得绕过这里直接修改预约。
- `app.js` / `style.css`：中文双栏工作台、患者会话、队列、摘要、事件日志。
- `server.mjs`：零第三方依赖的本地静态服务。
- `workflow.test.mjs`：核心流程与状态不变量检查，运行 `npm test`。

真实接入前应将存储与业务动作移到服务端，并加入身份权限、持久化事务与消息重试。当前只预留适配边界，未连接 Dify、LangGraph、n8n 或 Chatwoot。

## 已验证

自动检查覆盖：常见损伤预约与改取消、术后审核拦截与补资料、拒绝接诊、保险三种结果、指定人员与占用冲突、人工接管与风险处理、投诉和未知需求分流、术后叠加保险双重门槛。Chrome 实际操作验证术后资料收集 → 医疗审核 → 原会话恢复 → 匹配 PT → 预约成功。

## 可点击工作链路（MVP 02）

工作台上方新增 7 个可点击节点：理解与收集、联系医生、查询保险、匹配与排班、预约执行、回到患者会话、人工协作。

- 点击节点查看实际动作列表；点击具体动作查看发起方、接收方、请求字段、返回结果、任务编号和执行时间。
- 医疗审核保留每轮提交时的资料快照。补资料后形成新一轮任务；原任务、医生回复和下一轮请求可分别查看。
- 保险展示工具查询请求、Mock 返回结果与规则、保险专员任务、费用确认回传；排班展示查询条件和返回时段；预约展示提交和确认回执。
- “去当前处理位置”定位到审核 / 保险 / 人工操作区；“补齐本轮模拟资料”快速推进收集环节，仍保留逐条患者对话，医疗审核和保险人工确认不会自动代办。
- 未执行节点展示预期路径，标明尚未执行或无需此步。旧会话不会补造历史请求；建议点击顶部场景新建 Case 体验完整回执。
- `audit.js` 记录独立的请求快照与任务回执；`journey.js` 渲染工作链路。JSON 导出包含全部回执。

新增验证覆盖每轮审核快照隔离、保险查询与人工处理回传、排班结果及预约回执，共 11 组自动检查通过。Chrome 实测新增保险查询详情、人工确认后排班，以及医生任务生成和可点击详情。

## 多角色协作现场（MVP 03）

打开页面默认进入“多角色协作现场”。五个手机式纵向窗口分别展示患者、Front Desk Agent、医生 / 人工人员、保险服务、预约系统。顶部脑图概括目标、条件和分支，窗口上方的连线标注 Agent 与各角色的联系。未参与的角色保持待命，不伪造会话。

### 推荐演示方式

1. 点击“先查保险，再决定”。点“下一步”两次，观察保险服务收到查询、返回资格，患者端收到结果；此时预约系统仍未调用。
2. 在患者窗口选择“暂不就诊”，流程结束且不占用预约；或选择“继续了解并预约”，再描述需求，继续医疗分流及排班。
3. 点击“术后康复 · 联系医生”，选择“自动演示”。模拟患者逐项提供资料，Agent 发给林悦医生，模拟医生回复并匹配 PT，Agent 查询排班，模拟患者选择时段，预约系统确认，结果返回患者。
4. 点击“暂停演示”即可自行操作。医生窗口可填写意见并选择接受 / 补资料 / 不适合；保险窗口可人工确认；患者窗口可输入消息、选择时段、改约和取消。
5. 点击消息上的“查看这次请求与回执”展开真实保存的 Mock 请求 / 输出。点击脑图分支可定位到对应角色窗口。
6. 顶部“切换诊所工作台”保留原版 Case 队列、结构化摘要及可点击工作链路。历史 Case 保留，新的多角色请求只从新增操作开始记录。

“自动演示”和“下一步”会代入模拟患者与工作人员执行默认分支：医生默认接受、保险人工默认可覆盖、不支持默认患者自费、患者默认继续就诊。它们是会议演示控制，不是 Agent 自行获得了医疗审批或患者授权。暂停后手动选择可演示其他分支。风险场景会停留在人工跟进，不自动预约。

保险优先场景已新增明确的“等待患者决定”状态。先查保险不要求患者预先提交病史；继续就诊后按实际需求重新分流，术后情况仍要求医生审核，不重复查询已确认的保险。

### 看诊后授权场景（MVP 04）

新增“看诊后授权 · MRI/CT + 康复”场景：患者完成看诊后，Agent 根据医生病历同时提交 MRI / CT 影像授权，以及康复疗程授权。康复申请会显示医生申请与 PT 申请两种责任路径、申请次数（如 8–10 次）和治疗计划。保险授权结果支持四种分支：批准、需要补资料、拒绝、医生申述。补资料会回到患者会话重新提交；医生申述会创建林悦医生任务，提交后重新回到保险审核。所有申请、回执、轮次和状态都显示在保险 / 医生手机窗口、脑图和事件轨迹中。

新增 `scene.js`（多角色界面和逐步演示）、`scene.test.mjs`（八种场景的闭环验证）。运行 `npm test` 可检查全部 21 项：包括先查保险后拒绝就诊不创建预约、确认后再走医疗审核、多轮医生审核资料快照及原有预约状态约束。会话中的外部联系与角色回复均为本地模拟，未接入真实医生通信、保险商或排班平台。
